# v0.2 Current Fixture Selection

## 数据职责

```text
Official Schedule Source
→ canonical fixtures
→ Fixture State Normalizer
→ displayFixtures
→ Shortcut
→ Canvases
```

赛程是赛前事实；赛果是赛后事实。Current Fixture Selection 不读取 ResultCandidate，不推断终场，也不参与积分结算。`fixtures` 保存权威赛程和历史赛果，`displayFixtures` 是面向 Renderer 的当前比赛周投影。

## 选择合同

按 `round` 分组，并以该周最早 kickoff 为边界。默认提前 24 小时切换到下一比赛周：

- 第一组比赛前：显示最近未来周；
- kickoff 起至下一周切换窗口前：显示本周；
- 本周已全部进入明确终态：仍显示最近结束周；
- 下一周 kickoff 前 24 小时：切换到下一周；
- 最后一周之后：继续显示最后一周。

选择只依赖固定 `now`、Asia/Shanghai kickoff 与赛历，不依赖“最后一个有比分的比赛”。`scheduled` 到达 kickoff 后仅派生 `effectiveStatus: live`；时间绝不派生 `finished`。

确定性 season-flow 回归连续覆盖 9 月 5 日赛前/赛中/赛果结算、9 月 11 日 19:39 与 19:40 的切换边界、9 月 12 日部分和全部完赛、9 月 18 日切换边界，以及 9 月 19 日/21 日最后一轮。最后一轮完成后仍保留第 22 周，不返回空列表或旧轮次。

## 发布刷新

```bash
npm run fixtures:sync -- --dry-run
npm run fixtures:sync -- --dry-run --now=2026-09-11T19:40:00+08:00
```

`fixtures:sync` 先验证当前文件，再在内存中 normalize 和复验。只有 `effectiveStatus`、`displayRound`、`displaySelectionReason` 或 `displayFixtures` 实际变化时才事务式写入；仅时间戳变化不会产生每日噪声提交。GitHub Action 每天 19:40（Asia/Shanghai）运行，验证、测试全部通过后才发布数据。Fixture 与 Result 两个 Action 使用同一并发组，避免同时写开发分支。

## Shortcut 合同

生产 Shortcut 的 Repeat 输入必须读取根级 `displayFixtures`，而不是 canonical `fixtures`。这只是读取已派生列表；当前轮次、时间和状态判断均不进入 Shortcut。模板 ID、子 View ID 与链式 Update View 规则保持不变。
