# 决策记录

## ADR-001：Canvases 不直接抓取赛事网页

原因：官方正文为图片，HTML 和图片路径均可能变化，且未来多个客户端需要复用数据。

决定：增加 Adapter 层，客户端只依赖经验证的统一 JSON。

## ADR-002：未知趋势不伪造

原因：官方快照未提供 previous rank，单靠当前表不能推导可信趋势。

决定：`previousRank` 与 `trend` 均为 `null`，UI 显示 `—`。

## ADR-003：先提供平台无关 View Model

状态：Superseded by ADR-005。

原因：现有资料无法唯一识别 Canvases 产品和 API。

决定：不根据 Scriptable 猜测 API；先完成经过测试的数据层和 Web 参考 UI，待官方文档到位后只新增 Renderer。

## ADR-004：Canvases Native Renderer 必须以真实 App 资料为依据

状态：Superseded by ADR-005。

原因：目标产品已通过 TestFlight 邀请确认，但公开页面没有运行时、组件、网络、存储或项目格式文档。将 Scriptable 或 SwiftUI 的名称套入 Canvases 会产生不可验证实现。

决定：保留现有 Unified View Model 和 Web Reference Renderer，不创建猜测性原生代码。拿到新建项目默认代码、Network/Layout 文档或官方 Sample 后，先完成 Hello World 与 HTTP JSON Probe，再实现 Native Renderer。

编号说明：ADR-002 已用于“未知趋势不伪造”，为保持决策历史稳定，本决策使用 ADR-004。

## ADR-005：Shortcuts-driven Canvases architecture

状态：Accepted。

### Context

用户提供的官方 Canvases User Guide 摘要确认：Canvases 使用 Visual Editor 创建 Widget，通过 Shortcuts Actions 更新具有稳定 ID 的 Views，并明确没有需要编写的应用内代码。

### Decision

采用：

```text
GitHub standings.json
        ↓
iOS Shortcuts
        ↓
Canvases Views / Grid Template
        ↓
Widget
```

Web Reference Renderer 仅用于调试、数据校验和桌面预览。

### Consequences

优点：

- 符合官方工作流；
- 不引入虚构 Runtime；
- 可利用 Shortcuts Automation；
- Canvas 专注布局，数据层继续复用。

限制：

- iOS Widget 刷新受系统预算影响；
- Shortcut 是运行依赖；
- Canvas 设计、Shortcut 构建和验证主要需要真机操作；
- 网络/校验失败时依赖“不替换现有 Views”保留最后成功画面。

编号说明：任务建议使用 ADR-003，但该编号已存在。为保持历史引用稳定，不重编号旧决策，本决策使用 ADR-005。
