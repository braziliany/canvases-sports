# v0.2 Phase 5 · Result Adapter

Phase 5 增加一个受控的自动赛果发现入口，同时保留人工确认边界：

```text
Source → Snapshot → Adapter → ResultObservation
→ Fixture Matcher → ResultCandidate → Human Review
→ Authoritative Fixture → Derived Standings → Renderer
```

## 第一版来源

- 来源：扬子晚报/紫牛新闻《“苏超”第19周比赛最终战报》
- URL：<https://wap.yzwb.net/wap/news/5004565.html>
- 类型：`official-republish`
- 快照：`data/sources/results/2026-08-29-w19-yangzi-evening-news.json`

快照只保存解析需要的来源元数据、比赛上下文与三行赛果文本，不保存整页资源。测试只读取固定快照，不访问实时网页，也不把模型记忆或猜测写成正式比分。

## 职责边界

- Adapter：只把受控快照转换为 `ResultObservation`。
- Matcher：只根据 league、season、round、date、homeTeam、awayTeam 唯一匹配 fixture。
- Candidate Layer：复用既有 ResultCandidate schema 与 ID 策略。
- Review：仍由 `results:confirm` 和精确 `CONFIRM` 将 Candidate 转为正式事实。
- Standings：仍只从明确 `status: finished` 且比分完整的 fixtures 派生。

`ResultObservation` 包含 `leagueId`、赛季、赛程周、比赛日期、主客队、比分、来源名称、来源类型、URL 与观察时间；它不包含 `reviewStatus` 或 `confirmedAt`。

## Fixture 匹配

- Exact Match：唯一匹配才可生成 Candidate。
- No Match：报告 `FixtureMatchError`，不生成 Candidate。
- Ambiguous Match：报告 `AmbiguousFixtureError`，不选择第一项。

第一版不会仅凭两个球队名称全局匹配。

## 命令

```bash
npm run results:discover -- --dry-run
npm run results:discover
```

dry-run 是无写入预览。普通模式展示所有可新增 Candidate，只有精确输入 `ADD` 才使用既有 JSON 事务层写入 `data/result-candidates.json`。命令不会修改 fixtures、standings，不调用 `results:confirm`，也不会自动提交或发布。

隔离回归必须使用：

```bash
npm run results:discover -- --isolated-data-dir <absolute-existing-data-directory>
```

`results:add`、`results:discover` 与 `results:confirm` 共享同一隔离路径解析器。隔离目录必须是已存在的绝对目录，并且不得解析为仓库正式 `data/`；参数缺失、相对路径、目录不存在或正式目录冒充隔离目录都会在读取数据前显式失败，不会 fallback。

## 重复、多来源与冲突

- 相同 fixture、比分和 sourceUrl：视为同一发现，不重复创建。
- 相同 fixture、相同比分、不同来源：允许多来源 Candidate 共存。
- 相同 fixture、不同比分、不同来源：保留为冲突 Candidate，由人工复核。
- 不做自动投票、可信度评分或自动确认。

## 失败策略

无法解析受控结构会抛出 `AdapterParseError`；比分非法不产生 Observation；匹配为零或多项不产生 Candidate。第一版只读取仓库快照，没有在线抓取，因此没有运行时网络失败面。

核心原则：机器发现 Observation，人确认 Authoritative Fact。自动化处理机械工作，人处理不确定性。
