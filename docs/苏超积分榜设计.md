# 苏超积分榜设计

> v0.1 已真机冻结的范围是 `standings-grid → team-row → rank / team-name / goal-difference / points`。下文 TOP 8、Header、更新时间和失败行为是后续设计，不属于 v0.1 PoC 完成声明。见 [v0.1 PoC 归档](v0.1-dynamic-standings-poc.md)。

## 数据字段

Schema 继续保存排名、趋势、球队、已赛、胜、平、负、进球、失球、净胜球、积分、更新时间和来源。

趋势定义为 `previousRank - rank`。官方来源没有可靠的 `previousRank`，因此 v0.1 存储 `null`，所有界面显示 `—`，不生成人工趋势。

## Medium Widget 信息取舍

Medium Home Screen Widget 优先显示：

```text
排名  球队                  净胜球  积分
1     无锡                     +6   18
```

13 行必须完整生成。场次、胜、平、负、进球和失球保留在 JSON，首版不挤入 Medium Widget。若真机行高无法兼顾 13 行与可读性，先尝试缩短 Header、减小行间距和使用紧凑 Divider，不把球队字体压到不可读。

## TOP 8 动态逻辑

`qualification-label` 属于 `team-row` 模板，默认隐藏。Shortcut 每次根据数据中的 `rank` 判断：

- `rank == 8`：Visible = true，Text = `TOP 8 · 晋级区`；
- 其他排名：Visible = false。

因此晋级线随排名移动，不绑定扬州或任何球队名称。真机优先把标签呈现为第 8 行下方的轻量分隔信息。

## 更新时间

`updated-at` 显示 JSON 的 `updatedAt`，代表赛事数据时间。不得用 Shortcut 执行时间冒充数据更新时间。

## 生命周期与失败行为

- Shortcut 成功：构建 13 行后一次性替换 Grid Children，再更新 Header。
- 网络失败：不替换现有 Grid，保留最后成功画面。
- 无效 JSON：停止更新并保留现有画面。
- 首次安装且从未成功：Canvas 保留编辑器中的占位/空状态，等待首次成功运行。
- 再次打开：显示 CloudKit 中最近一次成功写入的 Canvas 状态。
- Widget：更新受 iOS 预算影响，可能比 Canvas 延迟约 15–60 分钟。
