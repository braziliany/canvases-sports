# v0.2 Phase 4 — ResultCandidate 人工录入入口

## 数据流

```text
可靠赛果 Observation
        ↓ npm run results:add
ResultCandidate
        ↓ npm run results:confirm -- <candidateId>
Human Review
        ↓
Authoritative Fixture
        ↓
Derived standings.json
        ↓
Shortcut / Canvases Renderer
```

`results:add` 只创建候选记录。它不修改 fixtures、standings，不自动 confirm，也不执行 standings build。

## 使用

```bash
npm run results:add
```

CLI 依次完成：

1. 从正式 `data/fixtures.json` 列出 scheduled/live 的可录入比赛；
2. 通过序号或 fixture ID 选择比赛；
3. 输入主队和客队非负整数比分，`0` 合法；
4. 输入必填来源和可选 HTTP(S) 来源 URL；
5. 自动记录当前 ISO-8601 `observedAt`；
6. 展示完整 Candidate Preview；
7. 只有输入精确的 `ADD` 才写入 `data/result-candidates.json`。

其他任何确认输入都会取消，所有正式数据保持不变。

## 重复候选与多来源

同一 fixture 已有未审核 Candidate 时，CLI 会展示现有 ID、比分、来源和采集时间。只有输入精确的 `MORE` 才继续新增。不同来源候选允许共存，不覆盖、不自动去重。

Candidate ID 使用：

```text
<fixtureId>-result-<UTC timestamp token>
```

若同一时间戳已经存在，则追加 `-2`、`-3` 等后缀，保证唯一且保留原记录。

## 校验与写入安全

- 比分：仅非负安全整数；拒绝空值、负数、小数和文本。
- source：trim 后必须非空，不使用 `unknown`。
- sourceUrl：空输入转为 `null`；非空时只允许 HTTP/HTTPS。
- 新数据必须通过现有 `validateResultCandidates`，schema 没有为 CLI 改动。
- 写入复用 `json-file-transaction.js` 的临时文件和回滚机制。
- add 只提交 candidate 文件；fixtures 和 standings 不在事务目标中。

新增记录可直接交给：

```bash
npm run results:confirm -- <candidateId>
```

## Scope

本阶段没有实现自动抓取、外部网页调用、Hermes、实时比分、Webhook、Cron、GitHub Actions、自动 confirm、自动 standings build、自动发布或 Canvases/Shortcut 修改。

人工回归示例和单元测试中的比分都是 mock。正式 candidate 文件在测试结束后保持为空。
