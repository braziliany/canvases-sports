# Canvases Sports v0.2 · Match Result Settlement

状态：确定性结算层完成；等待可靠赛果输入。

## 设计原则

> 赛程是事实源，积分榜是派生数据。

```text
fixtures (source of truth)
→ standings calculator
→ standings.json (derived view)
→ Shortcut
→ Canvases
```

同一场比赛的状态与比分只在正式 `data/fixtures.json` 维护。不得再单独手工修改积分榜统计，否则会形成双重事实源。

## 结算条件

比赛只有同时满足以下条件才进入积分统计：

- 原始 `status === "finished"`；
- `homeScore`、`awayScore` 均为非负整数。

`effectiveStatus` 不参与赛果确认。scheduled、live、postponed、cancelled，以及 finished 但比分缺失的比赛全部忽略。`0:0` 是合法赛果。

## 当前过渡数据边界

正式 fixtures 目前只收录 2026-08-29 第 19 周三场，缺少此前完整逐场赛果。直接从这三场全量重建会错误清空已有积分，因此 build 使用：

```text
2026-08-15 官方积分榜快照（不可变历史基线）
+ 基线之后 fixtures 中明确 finished 的赛果
→ standings.json
```

基线来自 `data/sources/jiangsu-2026-08-15.json`，不是另一个需要同步手工维护的积分榜。完整历史 fixtures 回填后，应移除过渡基线，改为全赛季 fixtures 全量派生。

## 积分与排名规则

项目资料确认：胜 3、平 1、负 0。同分依次比较：

1. 相互比赛积分；
2. 相互比赛净胜球；
3. 相互比赛进球数；
4. 总净胜球；
5. 总进球数；
6. 公平竞赛积分；
7. 抽签。

计算器实现前五项。当前数据没有公平竞赛积分和抽签顺序；若前五项后仍同序，build 明确失败。对于受新赛果影响的同分组，如果缺少完整头对头赛果，也明确失败。未受新赛果影响的既有同分组继续保留官方基线顺序。

## 使用

```bash
npm run standings:build
npm run validate
npm test
```

重复执行 `standings:build` 会生成完全一致的结果。

## 单场测试示例

测试中将常州–无锡构造成 `finished` 且比分 `1:0`，预期：

- 常州：场次 10、胜 6、进球 14、失球 7、净胜球 7、积分 19、排名 1；
- 无锡：场次 10、负 2、进球 14、失球 9、净胜球 5、积分 18、排名 2。

该比分只存在于单元测试，不是正式赛果，不得写入生产 fixtures。
