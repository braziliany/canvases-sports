### v0.2 Dynamic Fixtures · 真机验证与冻结

完成：

- 使用独立的 `data/fixtures-device-test.json` 完成六种状态矩阵真机验证，正式 `data/fixtures.json` 未被测试数据污染。
- 验证 scheduled、live、finished、postponed、cancelled 的中文展示，以及 live 比分缺失容错。
- 验证完整比分显示 `主队比分 : 客队比分`；任一比分缺失时显示 `VS`。
- 真机确认 `常州 1 : 0 苏州 / 进行中` 与 `盐城 2 : 2 南通 / 已结束`。
- 将设备夹具纳入离线测试与 `npm run validate`。

关键结论：

- 状态归状态，比分归比分；不要让状态分支决定比分格式。
- `0` 是有效比分，必须检查值是否存在，不能使用数值真假判断。
- 避免为单一展示点堆叠嵌套 If、`hasScore` 和跨层“如果的结果”。
- 计算逻辑保持最小化，不改变 ADR-006 的链式 View Update。

冻结：v0.2 状态与比分渲染真机验证完成；后续扩展不应改动当前成功数据流，除非发现明确错误或出现新合同需求。

## 2026-08-24

### v0.1 Dynamic Standings PoC · 真机验证与冻结

完成：

- 真机验证 GitHub JSON → Shortcuts → Canvases Template → Widget 完整闭环。
- 使用 `Repeat with Each Item` 动态生成 13 个 `team-row`，不是手工写死 13 行。
- 验证 `rank`、`team.name`、`goalDifference`、`points` 四字段绑定。
- 验证每个 `Update View Created from Template` 的输出必须链式传入下一个 Update。
- 验证每轮最终 Updated View 组成 `Repeat Results`，再整体写入 `standings-grid.Children`。

调试结论：

- “13 行全部是无锡”不是 JSON 或 Repeat Item 错误，而是 Created View 更新引用链错误。
- Quick Look 证明每轮数据均变化后，应把排查重点转向 View 输入/输出连接。
- Magic Variable 名称相似时，应将字段保存为明确的 `currentRank`、`currentTeam`、`currentGoalDifference`、`currentPoints`。

冻结：

- v0.1 只声明四字段动态积分榜 PoC 完成。
- TOP 8 视觉、更新时间、自动刷新、缓存、异常 UI 等扩展不属于本阶段完成范围。
- 下一入口为 v0.2 Dynamic Fixtures；本次不开始开发。
