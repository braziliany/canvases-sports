# 开发日志

## 2026-08-25

### v0.2 Dynamic Fixtures Phase 1 · Data Layer

完成：

- 调查江苏省体育局、地方政府赛历和组委会第 19 周公告。
- 建立 `data/fixtures.json`，首批收录 8 月 29 日 3 场已公告比赛。
- 新增独立 Fixtures Schema、严格日期时间校验、唯一 ID、比分状态约束和时间排序。
- 新增江苏来源状态映射与完全离线的 fixtures 测试。
- 文档预留 `fixtures-grid`、`match-row` 及 6 个模板字段 View ID。

关键结论：

- 2026 常规赛按 22 个赛程周分散编排，不再使用传统每轮 6 场；`round` 在江苏数据中表示赛程周。
- 官方公告没有列场馆，`venue` 保持 `null`，不根据常用主场猜测。
- 19:40 开球时间由公开完整赛历交叉核验；对阵和日期以组委会公告为准。
- v0.2 必须复用 v0.1 的 Chained Update → Repeat Results → Grid.Children 模式。

未做：Canvas、Shortcut、真机 UI、自动刷新、复杂视觉；v0.1 standings 和 Shortcut 未修改。

## 2026-08-24

### v0.1 Dynamic Standings PoC · 真机验证与冻结

完成：

- 真机验证 GitHub JSON → Shortcuts → Canvases Template → Widget 完整闭环。
- 使用 `Repeat with Each Item` 动态生成 13 个 `team-row`，不是手工写死 13 行。
- 验证 `rank`、`team.name`、`goalDifference`、`points` 四字段绑定。
- 验证每个 `Update View Created from Template` 的输出必须链式传入下一个 Update。
- 验证每轮最终 Updated View 组成 `Repeat Results`，再整体写入 `standings-grid.Children`。

调试结论：

- “13 行全部是无锡”不是 JSON 或 Repeat Item 错误，而是 Created View 更新引用链错误。
- Quick Look 证明每轮数据均变化后，应把排查重点转向 View 输入/输出连接。
- Magic Variable 名称相似时，应将字段保存为明确的 `currentRank`、`currentTeam`、`currentGoalDifference`、`currentPoints`。

冻结：

- v0.1 只声明四字段动态积分榜 PoC 完成。
- TOP 8 视觉、更新时间、自动刷新、缓存、异常 UI 等扩展不属于本阶段完成范围。
- 下一入口为 v0.2 Dynamic Fixtures；本次不开始开发。

## 2026-08-21

### Phase 3 · Shortcuts + Grid Template 正式方案

完成：

- 根据用户提供的官方 User Guide 摘要，确认 Canvases 使用 Visual Editor + Shortcuts，无应用内代码 Runtime。
- 将正式数据流修正为 GitHub JSON → iOS Shortcut → Canvases Grid Template → Widget。
- 定义稳定 View IDs、Canvas View Tree、一列 Grid、Template Children 和动态 TOP 8 逻辑。
- 编写可在 iPhone 上逐步搭建的 Canvas 与 Shortcut 实施文档。

发现：

- Web `fetch`/`localStorage` 仅属于参考实现，不能作为 Canvases 原生能力。
- 真机 Canvas 可以立即收到更新，但 Home Screen Widget 仍受 iOS 刷新预算影响。

问题：

- 官方 User Guide 原文件尚未随任务附件进入仓库；当前只使用用户提供的 Guide 摘要，不扩展未确认 API。

后续结果：核心四字段动态积分榜已于 2026-08-24 归档为真机验证完成；当时计划的扩展验收项不计入 v0.1 冻结范围。
